# Sample Manager API — Personal Reference

This folder documents the HTTP API currently implemented by `SampleManagerApiController`.

The documentation is intended as a practical development reference for the Sample Manager Tool and LabVIEW integration.

## Base URL

Development profile:

```text
http://localhost:5227
```

API prefix:

```text
/api/v1
```

Therefore, for example:

```text
http://localhost:5227/api/v1/health
```

The host/port can change when the application is deployed. The `/api/v1` route prefix is the API contract.

## Content type

POST requests use JSON:

```http
Content-Type: application/json
```

Responses are JSON.

## Current endpoints

| Method | Endpoint | Purpose |
| --- | --- | --- |
| GET | `/api/v1/health` | Check API and database availability |
| GET | `/api/v1/users` | List enabled research users |
| GET | `/api/v1/batches?userId={userId}` | List batches belonging to an enabled user |
| GET | `/api/v1/batches/{id}` | Get complete batch metadata and substrate/pixel structure |
| GET | `/api/v1/devices?userId={userId}` | List devices/pixels belonging to an enabled user |
| GET | `/api/v1/devices/{id}` | Get metadata for one device/pixel |
| POST | `/api/v1/users` | Create a research user |
| POST | `/api/v1/devices/{deviceId}/measurements/jv` | Store a JV measurement |
| POST | `/api/v1/devices/{deviceId}/measurements/eqe` | Store an EQE measurement |

See:

- [GET endpoints](GET-endpoints.md)
- [POST endpoints](POST-endpoints.md)

## Identifier format

Users, batches, substrates/samples, devices/pixels, stacks, stack layers, and measurements use GUID identifiers.

Example:

```text
04f40589-a621-4cb6-aa22-12a61d2289cb
```

## JSON naming

The API uses ASP.NET Core's default JSON serialization, so C# properties are returned in camel case.

Examples:

```text
ProductionDate -> productionDate
DeviceStackId  -> deviceStackId
MeasuredAt     -> measuredAt
```

## Dates and times

Batch production dates are dates without a time component:

```json
"productionDate": "2026-09-10"
```

Measurement timestamps are stored in UTC. Example:

```json
"measuredAt": "2026-09-10T09:35:00Z"
```

A measurement POST may send `measuredAt` with an explicit offset. If it is omitted, the server uses the current UTC time.

## Null values

Several metadata and measurement-result fields are nullable. A valid response may therefore contain `null`.

Example:

```json
{
  "area": null,
  "notes": null,
  "deviceStackId": null,
  "deviceStack": null
}
```

For measurement POST requests, blank `dataPath` and `notes` strings are normalized to `null` before being stored.

## Error responses

Some controller errors use a simple JSON object:

```json
{
  "error": "Batch not found."
}
```

The API also uses `[ApiController]`. Invalid request models, missing required JSON properties, malformed GUIDs, and similar model-binding errors can therefore return an automatic HTTP `400 Bad Request` validation response similar to:

```json
{
  "type": "https://tools.ietf.org/html/rfc9110#section-15.5.1",
  "title": "One or more validation errors occurred.",
  "status": 400,
  "errors": {
    "Common": [
      "The Common field is required."
    ]
  },
  "traceId": "..."
}
```

The exact validation fields and `traceId` are generated by ASP.NET Core and should not be treated as fixed application data.

## HTTP status codes currently used

| Status | Meaning in this API |
| --- | --- |
| `200 OK` | Successful GET |
| `201 Created` | User or measurement successfully created |
| `400 Bad Request` | Missing query input, invalid JSON/model, or model-binding failure |
| `404 Not Found` | Requested user, batch, or device does not exist in the expected context |
| `409 Conflict` | Attempt to create a user whose name already exists |
| `503 Service Unavailable` | Health check cannot connect to the database |

## Important terminology

The database model uses these names:

```text
Batch
  -> Sample
      -> Device
```

In the user interface these correspond approximately to:

```text
Batch
  -> Substrate
      -> Pixel
```

The API currently keeps the existing public JSON naming:

- batch collections contain `substrates`
- each substrate contains `devices`
- each device exposes its `pixel` name

## Measurements

Measurements belong directly to a `Device` (pixel).

Current supported measurement types:

```text
JV
EQE
```

Every measurement has common metadata:

```json
{
  "measuredAt": "2026-09-10T09:35:00Z",
  "dataPath": "C:\\Arkeo\\Results\\example.csv",
  "notes": "Optional note"
}
```

and a measurement-type-specific `specific` object. See [POST endpoints](POST-endpoints.md) for complete request JSON examples.
